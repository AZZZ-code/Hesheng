# 合声

合声把 Windows 正在一台设备上播放的声音，同时送到另一台音箱或耳机。主音箱继续播放原声，副音箱可以单独调音和补偿延迟。

## 下载与首次使用

1. 在 GitHub Releases 下载 `Hesheng-0.2.0-win-x64.zip`。适用于 Windows 10 / 11 x64。完整解压到一个可写目录，保留所有文件和子目录，再双击 `Hesheng.exe`。发布包自带 .NET 10 桌面运行时，使用现有音频驱动，普通用户即可运行。
2. 第一次打开会显示四步教程，可以边看边操作。关闭后可从右上角「使用教程」重新进入。
3. 在「播放」选择主音箱与副音箱。程序会枚举这台电脑当前可用的 Windows 播放端点，并优先选中系统默认端点作为主音箱。副音箱由你指定。列表中可能包含蓝牙耳机、USB 音箱、显示器和虚拟音频设备。
4. 点击「开始镜像」，出现「正在镜像」后点「播放测试音」。两端都应该听到三声。日常使用中，送往主音箱的系统混音也会送到副音箱。运行时可以更换设备，点「应用切换」生效。

## 副音箱均衡器

播放一段熟悉的音乐，先听「原声」，再试「人声」「低音」或「夜间」。80 Hz 主要影响低音，250 Hz 影响厚度，1 kHz 与 4 kHz 影响人声和清晰度，10 kHz 影响明亮感。一次只动一个推子，先尝试 1–2 dB。提高频段后如果出现失真，可以降低前级增益。点击「效果已开启」旁通均衡器和前级，比较前后的听感，再点一次恢复。输入名称可保存自己的预设，「复位为原声」会把推子和前级归零。

## 时间对齐

把延迟设为 0 ms，播放有清晰鼓点的音乐或反复播放测试音。如果副音箱先响，每次增加 5 ms，听到两下合成一下为止。回声加重时向小的方向调。范围为 0–300 ms；副音箱在 0 ms 时已经较晚，就保持 0 ms。这项补偿只会推迟副音箱，均衡器旁通时也会生效。

## 设备与设置

- 没有设备或只看到一个设备时，先在 Windows「设置 → 系统 → 声音」确认第二台设备已连接且可用于播放，再回到合声点「刷新设备」。
- 测试音能响但某个应用的声音没有同步时，在 Windows 音量合成器中确认该应用正在使用选定的主音箱。镜像依赖共享模式，独占播放和受保护的音频可能无法采集。
- 移动到另一台电脑时使用干净的发布包。每次启动都会重新枚举端点，配置中的设备离线时可以重新选择。软件不会为了匹配配置而修改 Windows 默认输出。
- 设备、音效、外观和教程状态保存在程序旁的 `settings.json` 中。均衡器按副音箱保存，延迟按主副音箱组合保存。升级前退出合声，保留自己的 `settings.json` 即可。首次迁移上游版本时可将原来的 `config.ini` 复制到程序旁。
- 最小化后从托盘恢复，关闭窗口即退出。`Hesheng.exe --play` 可启动已保存且仍在线的组合。旧版 WASAPI Bridge 占用镜像时，请先退出旧版。
- 切勿将个人 `settings.json` 或 `config.ini` 打包进公开版本。下载的源码和发行包都不需要填入作者的设备名称或 ID。

## 从源码构建与测试

在 Windows x64 使用 .NET 10 SDK 和 LLVM-MinGW UCRT x86_64 构建。已验证的组合是 .NET SDK 10.0.404 和 LLVM-MinGW 20261117。miniaudio 源码已随项目提供，首次构建会从 NuGet 获取微软桌面运行时。

```powershell
.\build.ps1 -Toolchain D:\tools\llvm-mingw-20261117-ucrt-x86_64
```

构建脚本会运行原声旁通、滤波增益、声道隔离和延迟测试，并从全新的目录生成 `dist\Hesheng-0.2.0-win-x64.zip`。把这个 ZIP 作为 Release 附件发布。在 Windows 桌面会话中，还可以运行首次启动回归测试。测试会解压到单独目录、启动应用、验证教程与设备列表，再验证重开行为。测试前请先退出已打开的合声。

```powershell
powershell.exe -NoProfile -STA -File .\tests\FirstRun.ps1 -Package .\dist\Hesheng-0.2.0-win-x64.zip
```
